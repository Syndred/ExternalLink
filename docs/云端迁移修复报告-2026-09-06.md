# ExternalLink 云端迁移修复报告（2026-09-06）

## 故障

- 首次迁移报错：`Too many subrequests by single Worker invocation`。
- 根因是 Worker 对 21 个状态文档和每条时间线事件分别执行一次 Neon HTTP 查询；数据量超过 Cloudflare 免费 Worker 单次 50 个子请求上限。
- 旧请求在报错前可能已经写入部分文档，因此不能简单清空或强制覆盖。

## 修复

- 状态文档通过 PostgreSQL `jsonb_to_recordset` 一次批量写入。
- 时间线修订同样批量写入，并按工作区、事件 ID、操作和事件内容跳过已经落库的记录。
- 所有迁移写入由 Neon `sql.transaction()` 放入一次 HTTP 请求内的原子事务。
- 重试前比较已写入的云端文档：已有内容与本机相同则安全续传；发现任一不同文档时返回 409 并拒绝覆盖。
- 日常 `submissionTimeline` 更新也改为批量写入，避免大量动态变更再次触发同类错误。

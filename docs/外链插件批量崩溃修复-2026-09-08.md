# 外链插件批量崩溃修复报告（2026-09-08）

## 现象与根因

点击侧栏“开始提交”后，扩展会按 `destination × Profile` 展开队列。当前种子有 2,905 个外链、6 个 Profile，可展开约 17,250 个待办组合。旧实现对每个任务复制完整 Profile 文案与媒体配置，并把整批任务反复写入本地存储、回传侧栏、一次性渲染。压力测算中，分组队列序列化达到约 234MB，超过 Chrome 扩展页面稳定承载范围；这与用户看到的“扩展崩溃”一致。

## 已修复

1. Profile 配置每个批次只构建一次、每个 Profile 只保存一份。
2. `activeBatchRun` 使用 v3 紧凑快照：destination 单独保存，任务使用 tuple 保存；17,250 个任务当前复测快照约 1.21MiB。
3. Side Panel 只收取/渲染当前 180 条任务窗口，当前复测约 107KiB；统计显示全批真实总数，窗口随运行位置滚动。
4. 队列循环加单实例锁，避免多个 `processQueue` 同时抢占并发位。
5. 建页失败时 running 任务会正确转为失败；最后一个任务页签关闭后会刷新为 finished / waiting_manual，不再永远显示运行中。
6. 后台保存最近 400 条结构化日志，记录 runId、阶段、任务序号、域名、Profile、状态、失败原因与异常栈。侧栏关闭重开仍可读取，并提供“复制日志”。

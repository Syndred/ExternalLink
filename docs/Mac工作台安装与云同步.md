# Mac 工作台安装与云同步

Mac 与 Windows 使用同一个正式 D1 + R2 工作区 `default`。Git 同步的是程序；站点资料、长短描述、图片引用、逐站提交内容与进度通过云端接口同步。不要复制另一台设备的浏览器目录、SQLite 数据库或配对凭据。

## 首次连接

需要已安装 Google Chrome 和 Node.js 24.21 或更新版本。在 Mac 已有的 ExternalLink 项目目录运行：

```bash
git pull --ff-only
bash executor/连接云端.command
```

首次连接会安装程序依赖，通过已有 Cloudflare 授权登记一个独立设备，再核对云端设备身份。没有 Cloudflare 授权时，会打开官方登录页面；这一步需要账户所有者完成。凭据仅保存到本机 `~/.externallink-executor`，不显示或提交到 Git，不需要手动复制密钥。

已有配对或登记文件时保留原设备身份；旧版配对要求先迁移，不覆盖本机记录。新设备默认暂停投稿，仅查看、编辑资料、登记进度和同步。Mac 显示整个工作区的外链总览，Windows 的任务执行权不会被复制到 Mac。

## 日常打开与更新

```bash
git pull --ff-only
bash executor/打开外链助手.command
```

启动器打开现有 Chrome 中的普通工作台 `http://127.0.0.1:19389/`，自动处理工作台解锁，不依赖受保护的扩展设置页。后台守护每 15 秒检查本机服务；关闭终端后继续运行。Mac 当前入口不安装登录启动项，重新启动电脑后需要打开工作台。

“从云端刷新”读取其他电脑的新资料及进度。资料修改经版本检查与独立回读保存；进度先进入本机持久队列，断网时保留，联网后重试。结构化文字和证据链接即可登记，不要求每条保存截图。

## 验证范围

Windows 工作台直接操作、队列重启恢复和实际 D1 回读已验证。Mac 浏览器启动参数、Unix 守护地址、首次设备身份校验、默认暂停及已有数据保护通过自动测试；尚未在实体 Mac 登录、安装或运行，不能把这些代码测试当成换机全过程验收。

首次连接后应核对工作区 `default`、站点资料数量、JevPlay 外链总览数量及一条现有进度，之后用两个设备分别刷新确认一致。不会自动开始投稿。

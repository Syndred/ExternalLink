# 本机打开与旧界面清理

## 这台 Windows 电脑

桌面已有“外链助手”快捷方式，双击即可。它调用项目已有的 `executor/scripts/open-workbench.mjs`，检查并启动本机服务，在 Chrome 打开工作台并处理解锁；无需手动复制访问令牌。

首次检查仅确认启动进程成功，未确认浏览器窗口可见，属于不充分验收。随后修复 Windows 浏览器被隐藏启动的问题：Chrome 使用可见启动并请求新窗口，后台服务继续隐藏运行。重新执行同一快捷方式后，系统确认可见窗口标题为“外链助手 · 工作台 - Google Chrome”，见 `evidence/cloud-recovery-2026-09-30/shortcut-visible.json`。

工作台是原插件的批量执行与台账配套入口，不能替代插件全部内容。它提供任务范围预览与执行、暂停继续、任务证据与接管、外链总览、资料文字编辑和进度同步；当前网页检测与填写、评论生成、媒体上传、外链库导入管理、完整产品资料和全局设置仍通过插件。原插件仍是完整使用入口，不应把网页工作台称为插件的完整替代。

备用入口：双击项目中的 `executor/打开外链助手.cmd`。服务正在运行且已解锁时，可直接访问 `http://127.0.0.1:19389/`。

## 旧界面清理

此前为了兼容已有任务，在侧栏折叠保留了“旧任务与历史记录”。本次明确从侧栏移除整个旧任务 UI，包括旧运行状态、暂停/继续/停止、旧待人工列表和旧报告按钮；新执行器的任务、证据和待办操作仍在运行工作台中。移除设置页的旧并发输入和对应保存读取逻辑，保存当前配置不删除既有历史配置。删除不再使用的旧面板样式。

历史任务、旧记录与后台恢复处理没有删除；这次清理没有恢复投稿，也没有对外站重新提交。扩展源码的主导航只保留运行工作台、当前网页助手、外链库。当前网页助手属于人工处理当前站点的功能，并非另一个批量提交入口。

按钮清单已重新生成：侧栏 44、设置页 32、独立工作台 14，共 90 个按钮实例；来源是隔离浏览器中的完整页面及动态组件，不代表 90 次真实投稿点击。

浏览器已经加载到内存的旧扩展不会因 Git 更新自动刷新。当前受支持工具无法重载日常 Chrome 中的那份实例；工作台已加载新代码，可直接使用。旧扩展安装实例若继续使用，仍须在其所在 Chrome 中重新加载一次，不能把源码清理当作该步骤已经完成。

## 验证

完整页面浏览器回归检查侧栏切换和选定范围传递无异常，旧面板完全不存在；设置页保存成功且历史并发配置保持原值。全量测试结果见 `evidence/cloud-recovery-2026-09-30/full-tests.txt`，截图和按钮清单见 `evidence/ui-simplification-2026-09-30/`。

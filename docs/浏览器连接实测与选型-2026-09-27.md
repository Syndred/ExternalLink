# 浏览器连接实测与选型（2026-09-27）

## 决定

**批量执行器的浏览器层选 Playwright＋独立 Chromium。**保留 Ego 日常使用。agent-browser 已证明可执行普通网页任务，但本机快速关闭重启出现一次连接错误，因此本轮只作为辅助候选。Steel 和 Browserbase 未实测，不把它们列成通过或失败。

当前证据从“只有官方资料”推进到“本机独立浏览器控制链已实测”。这不是两千站生产验收，也没有解除或重试此前被拒绝的扩展内部页访问。

后续已补 [主代理原生接管与执行进程退出后的重连实测](总控接管实测-2026-09-27.md)：两个工具均能在页面操作失败后由 Computer Use 介入；Playwright 独立 Browser Host 还通过了 worker 被强制结束后的原页接管与恢复。

## 环境与范围

- macOS arm64；隔离测试运行时 Node **24.21.0**，项目原有 Node 22 未修改。
- agent-browser **0.38.1**；Chrome for Testing **154.0.8037.57**。按该版本自带 core skill 的独立 session、snapshot/ref 流程执行。
- Playwright **1.63.0**；配套浏览器 **153.0.8010.12**。
- 本机 `127.0.0.1` 自有合成表单，及 [Selenium 官方 HTTPS 测试页](https://www.selenium.dev/selenium/web/web-form.html)。没有真实账号、真实目录投稿、生产数据库写入或插件重载。
- 两轮时间分别为北京时间 **13:41:00–13:41:20**、**13:42:24–13:42:45**。
- 首次手动启动曾填错下载后可执行文件路径；读取安装诊断给出的真实路径后启动成功。这是配置错误，不是浏览器拒绝。

## 结果

| 项目 | Playwright 两轮合计 | agent-browser 两轮合计 |
|---|---|---|
| 合成提交、服务器字段与回执逐项核对 | **18/18** | **18/18** |
| 中文文本、下拉框、勾选框、文件上传 SHA-256 | 全部一致 | 全部一致 |
| 延迟出现的表单 | **6/6** | **6/6** |
| 正常关闭后重开、读取已保存 Cookie/localStorage | **6/6** | **5/6**；一次连接失败 |
| 强制结束浏览器，随后显式重新打开 | **2/2** | **2/2** |
| 新 profile 隔离 | **2/2** | 首轮路径过长；短名称修正后 **1/1** |
| 公网 HTTPS 访问 | **2/2** | **2/2** |
| 最后一轮关闭后核对本次浏览器进程消失 | 通过 | 通过 |

“强制结束后恢复”只验证已在先前正常关闭时落盘的合成 Cookie/localStorage。没有测试正在发送的任务恢复、刚产生但未保存的状态、操作系统重启、电脑关机或长期在线。耗时是诊断数据，两个工具的浏览器版本不同，不用于公平性能排名。

## agent-browser 的两类错误

1. 首轮隔离会话的完整 Unix socket 路径为 111 字节，超过工具报告的 103 字节上限。长 namespace 是本次测试配置问题。复测改成短 hash namespace 和 `a/b` session，隔离通过。
2. 第二轮第二次正常关闭后重开，返回 **`Failed to connect: No such file or directory (os error 2)`**。随后开始下一组合成表单时恢复，原失败仍保留。根因没有定位，不能直接断言是 daemon 竞态，也不能把后续成功抹掉该错误。

这两类是本地路径/连接错误，不是目标站验证码，也不是此前 Computer Use 的扩展协议策略拒绝。Playwright 本轮没有出现同类错误；小样本不能证明未来永不失败。

## 为什么选这条线

Playwright 当前直接满足连接、字段操作、文件上传、截图和独立 profile 的试验要求，并且适合由现有 TypeScript/Node 执行服务直接调用。日常批量流程可以设计为“领取任务 → 操作目标网站 → 记录回执”，不需要打开插件内部页。

后续栈选定：**Node 24/TypeScript＋Playwright 1.63.0 配套 Chromium＋pg-boss/Neon＋现有 Cloudflare Worker/R2/AI 接口**。执行环境先固定到本轮测过的 Node 24.21.0；早先 Node 22.12+ 是最低兼容候选，不算本轮实测环境。本轮没有安装 pg-boss、迁移数据库或实现生产执行器。下一关是隔离任务/证据回读、提交后回包丢失的防重投验证和真实小批量站点，不能直接放量两千站。

- **Steel**：本机 Docker CLI 存在，但 daemon 未运行，未启动 Steel 服务。它的 API/会话管理可以后续评估，本轮没有实例证据。[官方实现](https://github.com/steel-dev/steel-browser)
- **Browserbase / Browser Use Cloud**：本次没有可用云连接/API 配置，未创建付费或云会话。不能声称实测通过。[Browserbase 官方](https://docs.browserbase.com/welcome/introduction)
- **agent-browser**：已实测网页控制，但主执行器需要额外面对 CLI/daemon/socket 生命周期；本轮不增加这一层。[官方实现](https://github.com/vercel-labs/agent-browser)
- **Playwright**：本轮选定浏览器层，仍需业务队列、登记与人工分流。[官方文档](https://playwright.dev/docs/intro)

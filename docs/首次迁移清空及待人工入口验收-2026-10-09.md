# 首次迁移、清空与待人工入口验收

本轮从 `90d3316` 拉取远端最新代码后继续。使用独立临时SQLite、实际原执行器与工作台服务、带设备鉴权的隔离D1实现，以及Codex内置浏览器操作。生产工作区没有清空、导入或投稿。

| 原入口 | 当前界面操作 | 独立持久化核验 |
| --- | --- | --- |
| 清除所有数据 | 设置与备份 → 清空本机工作区；错误确认、取消、正确确认、重新连接 | 完整私有SQLite备份保留原任务、未知边界、固定范围及冲突编辑；清空后连接和本机队列移除，保持暂停；云端、浏览器标记文件与素材字节保持 |
| 首次迁移到云端 | 本机登记重新连接 → 设置与备份 → 首次迁移 → 选择原格式文件 → 预览 → 确认合并 | 实际云端回读产品描述、收藏与分组；导入计划完成；原云端run/task逐项保持。清空前另测待处理编辑时拒绝导入，没有为通过而丢弃冲突 |
| 执行 | 运行任务 → 任务范围 → 查看原任务 | 原任务编号及云端记录保持，详情显示原人工状态与操作；未调用检测、准备或投稿 |
| 外链 | 外链库 | 导入的新注解及原入口均显示；收藏分组与云端读回一致 |
| 批量 | 勾选两个入口 → 批量提交 → 仅填写 → 预览 | SQLite保存两个固定组合、原任务编号及仅填写/并发参数；未开始批次，云端任务保持 |
| 待人工 | 运行任务 → 任务范围：待人工处理 → 查看 | 实际服务筛选到原任务并打开详情；返回列表保持筛选。六种人工状态及人工确认待同步、产品/搜索交叉筛选另有浏览器回归 |

发现并修复两处界面差异：清空失败原因原本只显示在弹窗后方，现在直接显示在弹窗内且保留确认输入；任务范围原本没有待人工选项，现在支持原人工处理状态、结果未知及人工确认待同步，已收件任务不会因旧人工状态而误列。

测试中的随机端口曾导致重新连接提示“插件来源未授权”。定位为测试环境的工作台端口与原服务来源配置不一致，对齐后原程序正常重新连接；没有放宽产品来源校验。相关失败作为实测过程保留。

清空创建的完整备份含连接凭据，仅保留在本机私有备份目录。公开证据只保存检查结果、界面状态和测试脚本，不包含备份数据库。本文证明上述入口链路；全插件其他动态分支仍按总审计继续，不能把这组结果称为完整迁移。

# 表单语义与站点经验 — 2026-09-10

## 用户需求

1. Paid 可能是当前产品的收费类型，不能因此跳过外链站。
2. A 提交到 C 后学到的 C 站表单，切换到 B 应可复用；手动“可提交”标记不能消失。
3. 已填好的人工页面继续沿用 3.4.1 的保留机制。

## 3.4.2 实现

- 普通填表入口共用 `understandFormBeforeFill`，复用已存在的云端 `/v1/ai/plan`，把当前表单快照、当前项目资料、历史站点结构传给模型。仅接受当前快照字段的 fill/select/check；提交仍走既有代码预检和回执验证。
- 同一页签、同项目资料、同表单结构避免重复理解调用；换项目、换字段或阶段重新理解。异步等待后再次核对任务、当前项目和 DOM，防止执行旧计划。每次新理解计入已有无人值守模型预算。
- 本地付款检测结合字段标签、选项、字段分组和局部文字；明确收录费/结算动作保留付款闸门，含糊理由不写成永久 paid/broken。真实不确定的付款动作仍可能交人工。
- `siteAnnotations[站点].formKnowledge` 保存字段语义 profileKey/label/hint，以及不含填写答案的表单结构和最多 12 个阶段；沿用现有 siteAnnotations 云端同步与备份链路，不新增云端接口。
- 共享关系不含 A 的 value。B 读取后按 B 的 projectFields 解析；字段语义不匹配则不直接套用。旧版各 Profile 的 learnedFieldMappings 可提取语义复用，Profile 自己的映射优先。
- 用户手动标记保留；自动判断写入 lastAutomaticObservation。更新/取消标记保留已学表单，切 Profile 与存储变化时刷新标记。侧栏显示已记住的字段数量；在当前页标记“可提交”时也尝试采集当前表单。
- “可提交”描述站点能力，不代表 B 已提交。A/B 的提交状态与回执继续各自绑定。

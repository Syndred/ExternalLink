# DevPages 填表与动态修复（3.4.4）

## 用户问题与核查结论

- 在 DevPages 手动点检测后表单仍空，填表按钮长时间停在「填写中」。3.4.2 把模型规划放在本地字段填写之前，普通字段也被网络调用阻塞；侧栏检测还等待质量指标等附属请求。
- 手动点击网页提交按钮未接入成功记账。实时云端确认 `devpages.io/submit-a-tool::RspAi` 的成功记录和动态都缺失；同步元数据没有报错，因此不是「已有记录未同步」。
- 侧栏原来只能查看动态，缺少补记入口；历史 `unknown` 时间原样显示。
- 评论工作室原来预载产品描述；这不能证明截图中的文本是刚调用 AI 生成。另发现非 WordPress 检测和 generic 表单里的 message/body 等判断过宽，存在目录字段被误认评论的路径。
- Chrome 现场读到已加载 3.4.3，并在旧脚本中看到 `Extension context invalidated`。重载插件后旧页面需要刷新；本次增加导航回调和定时检测的失效保护。

## 实现

1. 检测成功后立即触发当前 Profile 的填表；预扫描和域名指标后台刷新，不占住填写入口。
2. 先复用站点字段经验并执行本地字段匹配，剩余必填/无效项才请求 AI；规划请求限制 25 秒。失败保留已填内容并显示原因。
3. 侧栏普通检测/填表仅填写，留在当前页；批次提交沿用批次配置。按页签防重复请求，绑定 URL 和 Profile，切换后拒绝旧填表结果。
4. 新增「登记外链动态」，选 Profile、状态、时间、备注及可选证据链接。复用现有时间线与成功记录接口；笔记不升级提交状态。
5. 在填写时绑定手动提交监听；只有真实用户点击/提交事件、表单产品网址相符且出现本次新增回执，才写入固定 Profile 的账本和动态。旧回执、错误 Profile 和程序合成点击不算成功。回执保存失败可从登记入口补记，并保留持久日志。
6. 非评论页隐藏评论生成和填入；收紧后台评论识别，产品描述不走评论生成。切换页面/项目后不接收旧评论生成结果。
7. 成功记账、动态增删改与侧栏刷新迁移共用串行队列，同一成功回读幂等；已有账本缺少对应事件时修复时间线。

# Neon 流量超额与增量同步修复（2026-09-21）

> 状态更新：当日已迁移到新 Neon 项目并完成生产回读；本文“配额恢复后的验收”已由 `docs/Neon新项目迁移-2026-09-21.md` 的迁移验收取代。

## 结论

台式机出现的 HTTP 402 不是登录或设备配置错误。Neon 控制台确认 `ExternalLink` 项目已用完当月网络传输额度：本月已使用 5.62 GB；项目仍在 Free 计划。Worker 能正常鉴权，但任何需要查询 Neon 的接口都会被上游 402 拒绝。

## 根因

- 插件启动时使用 `/v1/snapshot` 读取全部状态文档。
- 侧边栏刷新提交动态时也读取完整快照，实际只使用 `submissionRecords` 和 `submissionTimeline`。
- 侧边栏冷却时间只有 5 秒；多浏览器、多设备会重复下载包含大型 `sheetTableData` 的完整 JSON。
- `extension/table-library.json` 约 3.1 MB，可说明外链库正文是主要流量体量之一，但线上文档的精确响应大小需等配额恢复后再测。

## 已修复

- Worker 新增 `GET /v1/revisions`，只返回各状态文档修订号，不读取 JSON 正文。
- Worker 新增 `GET /v1/state/:key`，只读取指定文档。
- 插件已有相同云端修订时只请求修订号；只对修订发生变化的文档下载正文。
- 新设备或切换工作区时仍允许一次完整快照，保证首次初始化完整。
- 显式解决冲突会强制读取冲突文档，即使修订号相同也不会错误跳过。
- 本地正文缺失时会强制补拉；单文档响应不完整会中止且不推进修订号，避免永久漏同步。
- 多文档变化时顺序读取正文，避免瞬间并发大量 Neon 查询。
- 侧边栏仅检查两类提交动态文档，冷却时间从 5 秒提高到 60 秒。
- 检测到 402/配额超限后，后台写入重试延长为 60 分钟；本地待写队列继续持久保留。
- Submify 同步后的云端核验只读取 `sheetTableData`，不再回读所有状态文档。
- 扩展版本升级为 `3.7.1`。

## 配额恢复后的验收

以下是原计划的恢复后验收项；新项目迁移后已经完成云端数据和媒体回读，台式机界面回读仍按本清单执行：

1. 台式机执行 `git pull --ff-only origin main`，重新加载扩展并确认版本 `3.7.1`。
2. 使用桌面配置文件连接云端，先执行“从云端回读”，不要执行首次迁移或先点立即保存。
3. 连续刷新侧边栏，确认第二次只请求 `/v1/revisions`，修订未变时不请求大型正文。
4. 修改一条提交动态，确认只读取变化的 `submissionRecords` 或 `submissionTimeline`，并核对同一 `destinationKey + Profile` 的云端回读与界面显示。
5. 记录实际响应大小和 Neon Network transfer 增量，作为流量修复的最终生产验收。

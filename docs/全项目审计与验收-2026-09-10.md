## 验收口径

本轮检查源码真实调用路径并用故障用例复现，修复后重新执行。Node 测试包含纯函数、VM 中执行源码和静态契约检查，不能等同于 Chrome 实机端到端通过。

浏览器工具明确阻止访问扩展内部页面，本轮未绕过限制。因此设置页、侧栏、多选和批次按钮仍缺当前版本的实际点选验收。普通 DevPages 网页可访问。本轮没有新增公开提交或批量评论。

## 已复现并修复

| 编号 | 问题与后果 | 修复和回归 |
| --- | --- | --- |
| B1 | 点继续后内存恢复，持久状态仍 paused，重开后误恢复暂停 | 只允许显式继续跨越 paused → running；普通后台写入不能解除暂停，stopped 仍不可逆转 |
| B2 | 调度异常只改变内存，持久批次仍 running | 复用暂停流程保留队列、暂停自动页签并保存可恢复状态；旧批次异常不影响新批次或已停止状态 |
| S1 | 同一文档上传期间再次编辑，新修改的待同步标记被旧请求清除 | 对比上传值与修改序号，保留新版本待同步；队列落盘后再开始请求 |
| S2 | MV3 后台休眠/重启后，内存中的待同步任务丢失 | 初始化恢复持久 pending/conflict 队列 |
| S3 | 云端回读等待期间的本地编辑可能被覆盖；全局 mute 还会吞掉其他写入通知 | 回读前后核对状态、版本和配置；精确过滤自己回读的值，不忽略整个时间窗口 |
| S4 | 409 后移除待同步标记，随后自动回读可能覆盖本地冲突值 | 持久保留冲突和本地数据，侧栏自动回读给出冲突状态；恢复要求先备份并明确选择采用云端 |
| S5 | 上传中切换工作区，后续请求/旧响应可能串工作区 | 请求绑定起始配置，切换立即终止本轮；持久身份只含 endpoint/workspace，token 比较仅留内存 |
| S6 | 多份文档前一份上传成功、后一份失败时，前一份新版本号未保存，后续产生假冲突 | 每份文档收到确认即保存版本号与待同步状态，后续失败不撤销已确认进度 |
| U1 | 切换批量 Profile 后队列仍可能使用旧选择，晚返回响应覆盖新结果 | 显式传递本次选择，立即清旧队列，按请求序号丢弃旧响应 |
| U2 | 侧栏批次硬编码并发和 IndexNow，忽略设置 | 普通批量读取已保存选项；无人值守保持后台并发 1 |
| U3 | 未入库网页登记动态可能形成查不到的孤儿记录 | 登记时先保存外链站，再按同一规范化目标写入动态；入口继续对当前 HTTP 网页开放 |
| U4 | 切换资料/云端回读可丢失未保存草稿 | 保护站点编辑状态，回读前和响应后复核，暂不应用时显示真实原因 |
| C1 | 普通目录描述字段名为 comment 时误当博客评论 | 区分真实可见 WP/文章评论表单，填写和提交绑定同一个表单 |
| C2 | 评论点击提交但没有回执仍返回成功；WP 自动提交偏好越过仅填写 | 只有新回执才能确认；无回执转人工，明确 fillOnly 始终不点击提交 |
| C3 | 隐藏密码框、隐藏验证码、postalCode 被当成人机闸门 | 检查可见性与验证码语义，保留真正可见验证码/OTP 的人工处理 |
| C4 | SPA 切页后旧 AI 草稿或媒体结果写回新页 | 异步填写前校验页面上下文；本次提交或下一步导致的合法跳转仍按新回执判断 |

## 结构上的不足

- 现有测试中一部分只检查源码里是否存在某段字符串；B1 在这些测试全部通过时仍可复现。本轮新增实际执行函数的故障测试，后续涉及状态变更的修复继续按此补测。
- background/content 两个大文件分别承载大量状态机和平台流程，审查边界容易遗漏。本轮沿用现有模块和 helper 修复，未同时进行大规模拆文件，避免把行为修复和重构混在一起。
- 源码版本、Chrome 已加载版本、目标页已注入脚本是三种不同状态。源码检查通过后，仍必须重载扩展并刷新待测网页才能验证新逻辑。

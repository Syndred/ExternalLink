## 已实施的精简

| 旧入口或问题 | 处理 | 理由 |
| --- | --- | --- |
| popup.html / popup.js 独立四页 UI | 改成统一界面跳转 | Manifest 已使用侧栏；旧弹窗维护第二套资料、队列、配置与日志 |
| 侧栏顶部额外插入运行工作台 | 放进“运行工作台”标签，默认打开 | 避免新执行器和旧页面同时堆叠 |
| 旧“批量”标签和开始提交按钮 | 删除新批次入口与相关启动处理函数 | 与 Windows 执行器的开始按钮重复且使用不同引擎 |
| 分类开始 / 分组开始 | 合成“将当前筛选送到工作台” | 统一使用完整筛选结果与当前产品，只选范围，随后预览再开始 |
| 旧多产品勾选、仅填表、无人值守参数 | 从旧批量 UI 移除 | 原来只作用于旧引擎，容易被误认为新执行器设置 |
| 旧任务暂停、继续、停止、人工接手、证据和日志 | 放进“旧任务与历史记录” | 已有任务仍须可处理，不能删掉历史和证据 |
| 设置页重复执行器 | 移除整套执行面板，保留统一运行入口 | 设置页负责资料、外链库、配置和总览 |
| 设置页总览插在标签外 | 新增独立“外链总览”标签 | 切换资料/配置时不再一直显示长台账 |
| 独立工作台同时显示长台账和执行器 | 分成“运行任务”“外链总览与资料” | 日常任务与跨批次台账各有明确入口 |
| 暂停和继续同时显示 | 根据暂停状态显示其中一个 | 避免给出与当前状态相反的按钮 |
| 未提交任务的核验回执 | 隐藏 | 后端明确要求存在提交尝试；原按钮点击只会报错 |
| 已有尝试/回执、结束任务的接管 | 按真实后端条件控制 | 避免显示后端拒绝的接管操作 |
| 已接管任务再次接管 | 改为保留打开本站链接，移除重复接管按钮 | 避免重复交接 |
| 每个任务直接显示已审阅 / 有异议 | 收进“登记审阅”，当前已选状态禁用 | 保留不同审阅含义，减少常驻按钮 |
| 数百条待执行/结束任务直接平铺 | 收进“其余任务与历史结果” | 优先显示人工、待核验和当前运行任务；总数不变 |
| 补传云端、关闭待办页、恢复 D1、清除本机数据 | 维护区折叠；无待传数据时禁用补传 | 低频维护操作不再与开始按钮并列 |
| 独立工作台隐藏恢复按钮却留下空维护折叠 | 一并隐藏所属折叠 | 去掉空入口 |
| 修改产品、网址或上限仍可用旧预览开始 | 立即失效；迟到的旧预览响应也丢弃 | 避免提交范围与屏幕内容不一致 |
| 开始请求发送前按钮仍可连点 | 请求前立即禁用 | 避免重复启动 |

## 保留的功能及理由

检测、填表和提交本页属于当前网页操作，与常驻执行器批次不同。上一站/下一站是浏览队列，下一站按钮则用于当前填写流程结束后的推进。评论生成、历史恢复、媒体预检分别用于文本和附件；不同状态标记不互相替代。Quick Open 仅打开页面，不投稿，与工作台没有相同副作用。

设置中的提取网址、基于当前资料生成、保存资料分别是不同操作。连接云端、初次迁移、回读、上传并非重复：迁移和上传会写入，不能用刷新替代；因此保留在已有高级区。导出逐站台账、旧运行记录、旧批次报告和 JSON 备份的内容不同，保留各自上下文入口。原始表格字段用于兼容资料，没有删除保存数据。全局配置明确说明作用于网页助手/旧任务，新执行器范围和上限在工作台设置。

# ExternalLink 3.2.0 可信自动化升级与验收

## 目标

把批量提交从“能填表”升级为可恢复、可审计、可核验的完整执行系统，同时保持验证码、登录、OTP、付费、新 OAuth、法律确认和 Product Hunt 自定义发布流程的人工边界。

## 对标与取舍

- Stagehand：采用“AI 处理未知页面，代码处理已知且高风险动作”的混合架构；ExternalLink 的模型只能识别和填写，最终提交由确定性预检函数执行。
- Skyvern：采用 DOM + 标注截图 + 视觉模型的兜底方式；DOM 动作返回成功但页面状态未变化时，也会触发视觉兜底。
- Browser Use：采用任务、动作、页面状态和结果组成的运行轨迹；ExternalLink 进一步把 run / attempt / step 正规化写入 Neon，并将截图证据写入 R2。
- 没有直接引入上述运行时：本项目必须继续复用用户当前 Chrome 登录态、扩展侧栏、现有 Profile/媒体/账本和 Product Hunt 人工策略；替换成独立云浏览器会破坏这些既有能力。

## 已完成

- 扩展版本升级到 3.2.0。
- 新增本地有界 `automationRunLedger`，侧栏可导出最近一轮 JSON。
- 新增 `automationEventOutbox`：每个事件先与本地账本原子保存，再上传 Neon；Service Worker 启动及每 5 分钟重放，Worker 端 step ID 幂等。
- Neon 新增 run / attempt / step 三张表；支持 `running / paused / waiting_manual / stopped / finished`，重试次数和任务终态时间可追溯；晚到事件不能覆盖已结束状态。
- 页面快照覆盖原生字段、contenteditable、Lexical、ProseMirror、Quill、文件输入、ARIA/Radix 控件、iframe 摘要、DOM hash。
- 文本模型和视觉模型只允许 `fill / select / check / wait`，没有通用 click/submit 权限。
- 必填与浏览器校验通过后，代码可执行安全的 Next/Continue 多步骤导航，再走独立提交预检。
- 提交成功必须是本次动作后新增的页面回执、2xx 网络凭证或独立公开结果；URL 变化、标题变化和模型判断不能单独入账。
- 已点击但无回执记为 `submitted_unconfirmed` 并保留页签，不写 `submissionRecords`。
- 人工成功确认只存在于扩展侧栏，并校验当前 run、parked task 和随机 nonce；目标页面脚本不能伪造确认。
- 视觉截图使用内容摘要组成对象 ID，R2 已存在同 ID 但 SHA 不同则拒绝覆盖。
- 暂停/继续仍为同一个互斥按钮；“继续等待中的任务”只用于人工页签，不是继续整个批次。

## 真实验收

- Chrome 实际加载扩展显示 3.2.0，下述真实批次由该版本的 Service Worker 执行。最终源码在本轮复测后已请求重载，但 Chrome 安全策略禁止自动化回读 `chrome-extension://` 内部页，不额外声称已回读最终 Worker 实例。
- `run-mttr36sl` 使用 RainbowPetAI、仅填表模式跑真实队列：Neil Patel 页面稳定约 13 秒后判定没有目录字段，没有再误点跨站 `Try Free`；随后正常进入 Devpost 并识别 `Add your project` 入口。
- 点击停止后批次显示“已停止”；Neil Patel 待人工页签保留，Devpost 自动页签关闭。
- SideProjectors 真实页面可被侧栏识别为队列站点，并显示既有提交时间线与云端媒体 5 个文件。
- 没有点击任何第三方最终提交，也没有新增虚假成功记录。

## 明确保留的人工边界

验证码、登录/OTP、新 OAuth、付费、法律确认、站点禁止自动化，以及 Product Hunt 等高价值自定义发布流程仍停放给人工。除此之外，系统会优先走规则填表、AI 补全、视觉兜底、安全多步骤导航、确定性提交和证据核验；无法取得回执时绝不伪造成功。

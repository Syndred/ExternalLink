# 多设备强制云端回读修复（2026-09-21）

## 问题

另一台电脑连接新 Neon 工作区后，扩展提示“本地有待保存的云端修改，暂不覆盖本地数据”。原实现只允许对 `conflict` 状态执行备份后的强制回读；只有 `pending` 状态时没有继续入口，因此复制过浏览器 Profile 的电脑无法明确放弃旧缓存。

## 修复

- 扩展版本升级到 `3.7.2`。
- 手动点击“从云端回读”遇到 `pending` 或 `conflict` 时，都会先导出本地 JSON 备份。
- 用户确认备份已保存后，`pending` 状态会以 Neon 工作区为唯一真相源，完整覆盖本机 22 类状态键。
- 云端不存在的状态键会从本机缓存删除；已覆盖键对应的 pending、conflict 和 patch 队列会同时清空。
- 回读期间若本机数据或云端配置再次变化，仍中止覆盖，避免吞掉并发编辑。

## 台式机操作

1. `git pull --ff-only origin main`
2. 在扩展管理页重新加载 ExternalLink，确认版本 `3.7.2`。
3. 打开设置页，点击“从云端回读”。
4. 浏览器下载 JSON 备份后，在确认框选择继续。
5. 看到“云端回读成功”后再开始使用；不要点击“首次迁移到云端”。
